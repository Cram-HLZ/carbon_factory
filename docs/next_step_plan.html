Step 1B · 搭后端框架 + 对接前 3 个 GET 接口 （Day 1-2）

后端本质上就是「HTTP 转发算法 + 业务组装」。先做 3 个 GET，前端就能画 3 个页面。
# backend/algorithm_client.py
import httpx

ALGO_BASE = "http://localhost:8000/api/v1"
client = httpx.Client(timeout=10.0)

def call_algo(path: str, method="GET", **kw):
    r = client.request(method, f"{ALGO_BASE}{path}", **kw)
    return r.json()  # 返回 {code, message, data}
# backend/routes.py
from fastapi import APIRouter
from .algorithm_client import call_algo
router = APIRouter(prefix="/api")

@router.get("/carbon/overview")
async def overview():
    return call_algo("/carbon/overview")  # 直接透传，先不加工
里程碑：到这里「前端→后端→算法」链路通了，阶段1 验证成功一半。后续接口都是同样的转发套路。

Step 1C · 对接剩余接口 （Day 3）

POST 接口要把前端表单/点击事件接到后端，再转发给算法。
避坑：文档说 scaler 文件是 scaler_{equipment_id}.pkl，但实际 output/model_weight/ 下只有 scaler.pkl（无设备后缀）。联调归一化前先 ls output/model_weight/ 核对实际文件名，按实际加载。

关键风险与避坑清单

1. scaler 文件名不符：文档写 scaler_{id}.pkl，实际是 scaler.pkl。归一化代码按实际文件名写。
2. 模型未训练：output/model_weight/ 无 .pth 权重，/anomaly/detect 会返回 threshold_type: "fallback"（统计偏离度）。能联调，但精度低，上线前训练 5 台高耗能设备。
3. 缓存 30 秒：overview/heatmap/realtime 有内存缓存（services._CACHE_TTL=30.0）。改了数据不生效时，等 30s 或重启算法服务。
4. 时间格式：必须 ISO 8601 带 T，如 2026-08-21T14:30:00，否则 422。
5. CORS 开着 '*'：联调期 OK，上线前改白名单（阶段5 做）。
